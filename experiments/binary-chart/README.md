# Binary chart playground

An isolated UX study for a moving Bitcoin chart and selectable range-binary cells.
It has no wallet, signing, backend orders, liquidity access or real-money execution.
The production swap app is unchanged. Work is on `experimental/binary-chart`, based
on the preserved `usd8-dynamic-v1-working` milestone rather than the opcode experiment.

```sh
npm ci
npm run poc:chart
# http://127.0.0.1:5174/
# http://127.0.0.1:5174/?feed=demo for an explicitly simulated feed

npm run build:chart
# Self-contained page: experiments/binary-chart/dist/index.html
```

## UX decisions

- The time cursor stays anchored while real price history moves left and expiry
  columns approach from the right. A gentle vertical follow keeps the current price
  in view; hovering the chart holds the viewport to make targets easier to select.
- Price bins have fixed absolute bounds. Following the price or changing band size
  never changes an already selected trade's bounds, expiry or multiplier.
- Each column expires at a fixed 10-second boundary. Only the price **at expiry**
  counts, not a touch before expiry. A two-second entry cutoff prevents last-moment
  cell targets from accepting taps.
- Hover/focus previews the actual range, clock time, stake and total return. Click
  or Enter locks a paper trade. The position rail keeps it visible as the grid moves.
- Selected cells lock their illustrative multiplier; another tap cannot accidentally
  place a duplicate on that same range/expiry. Up to eight paper positions can be open.
- Price-band controls, a persistent amount per tap, visible paper balance, outcome
  feedback, keyboard access and responsive touch targets support exploration.
- The source mode is explicit. Switching modes starts a new paper session. Live
  failures never silently turn into simulated prices or fabricated wins.

## Price source

The default is Binance's public BTC/USDT aggregate-trade WebSocket:

```text
wss://data-stream.binance.vision/ws/btcusdt@aggTrade
```

The page backfills real one-second candles from `data-api.binance.vision`, and
polls the latest aggregate trade once a second if the stream is unavailable. Both
transports use the same market; REST backfill cannot overwrite newer streamed ticks.
The moving timeline anchors to source timestamps, avoiding device-clock skew. Receipt
age is checked separately: after five seconds without fresh data, paper entry pauses.
The stream reconnects with bounded exponential backoff. Some regions or browser policies
may block Binance; the user can explicitly choose the deterministic simulated feed.

Binance BTC/USDT is appropriate for this interaction study: free public access, no
API secret, frequent trades and historical backfill. It is one exchange's USDT price,
not a composite USD index. A later product can replace the feed adapter with an index;
this page makes no claim to be a settlement oracle.

References: [market-data-only endpoints](https://github.com/binance/binance-spot-api-docs/blob/master/faqs/market_data_only.md)
and [aggregate-trade stream](https://developers.binance.com/docs/binance-spot-api-docs/web-socket-streams).

## Paper outcomes and limitations

Multipliers are generated by an intentionally illustrative normal-distribution
model using recent observed variability. They are **not** executable maker quotes,
calibrated probabilities or a pricing recommendation. Balance starts at 100,000 paper sats and remains in memory.
Stakes are 500, 1,000, 2,000 or 5,000 sats; winning payouts round down to whole sats.
The BTC/USDT chart and range bounds keep their price denomination. Stake is deducted once; the displayed winning payout
is the total amount returned, including the stake.

The first actual source sample at or after expiry resolves a paper trade, provided
it arrives within two seconds of that expiry in source time. Lower range bounds are
inclusive, upper bounds exclusive. Missing expiry samples void the paper trade and
return its stake. Historical candles are for the chart, not late settlement inputs.
There is no persistent history or recovery across reloads. This is a chart experiment,
not the final option contract, oracle, quoting or settlement implementation.

## Validation

`npm run build:chart` type-checks the isolated browser code and builds a standalone
HTML page. `test/binary-chart.test.ts` covers expiry-vs-touch behavior, boundary
conditions, no double resolution, missing-data refunds, source validation and fixed
expiry identities. The regular unit-test command includes these tests.

Browser checks cover live Binance connectivity, desktop and 390px mobile layouts,
keyboard entry, virtual-balance changes, expiry resolution and an explicitly blocked
feed. No live swap services are restarted or changed to run this playground.
